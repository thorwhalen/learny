learny.tracing.difficulty#

Explanatory item difficulty: which item features make an item hard.

An item bank often carries features of every item — how many glyphs it has, how irregular its rhythm is, how frequent its words are — and a hypothesis that some of them drive difficulty. fit_feature_difficulty() tests that hypothesis against play. It fits the Linear Logistic Test Model (Fischer 1973) with a residual per item (the random-item extension of De Boeck 2008):

logit P(correct) = ability[student] - difficulty[item]
difficulty[item] = intercept + weights . features[item] + residual[item]

with Gaussian priors on every parameter, by maximum a posteriori and a Laplace approximation, so each weight comes with a standard deviation: which features matter, and how sure the fit is. The result predicts the difficulty of an item nobody has played yet from its features alone, which is the cold start for a new item.

This is the one place in learny.tracing that reads across students, so it follows the rule for that (decision 8 in docs/learner-model-design.md): it runs only when called, over a log it is handed, and what it learns leaves as an exported, reviewable artifact (FeatureDifficulty, JSON by to_dict()) that enters the learner model through the existing items= seam (apply()), never as a side effect of fitting.

A fitted explanatory difficulty model; see fit_feature_difficulty().

Features are stored standardised ((x - center) / scale over the fitted items), which is what the priors and the covariance refer to; weights() reports them in each feature’s own units. covariance is over (intercept, *weights) in the standardised form. residual_var is the prior variance of a new item’s departure from what its features predict, ability_mean and ability_var the fitted students’ ability distribution, on the scale of the bank’s given difficulties when the fit was anchored on them. residuals holds each fitted item’s own departure, as (mean, variance, *covariance with the coefficients); it carries the fitted students’ data, so apply() leaves it out unless asked. converged is false when an iteration cap was hit (a RuntimeWarning said so at fit time).

Per-attempt features (attempt_names, standardised over the fitted attempts by attempt_center and attempt_scale) add their weights after the item weights, so coef and covariance are over (intercept, *weights, *attempt weights); attempt_weights() reports them. They have no residual: an attempt’s setup moves the difficulty of whatever item it is played with by its weights alone.

apply(items, *, features=None, overwrite=False, use_residuals=False)[source]#

A copy of items with each item’s difficulty predicted from features.

Only items without a difficulty are filled unless overwrite=True; an item with no features is left as it is, and per-attempt features are taken at the fitted attempts’ average. The difficulty comes from the features alone unless use_residuals=True adds each fitted item’s own residual. That residual is learned from the fitted students’ answers, so feeding it back to estimate those same students counts their answers twice; with one or two learners it is mostly their own results (#18 review). The result is an item bank for the items= seam of LearnerModel.

The difficulty, in logits, of an item with these features.

For any item the residual is unknown, so its prior variance residual_var is added to the features’ part. Pass item_id of an item the model was fitted on to use that item’s own fitted residual instead, with its posterior variance and its covariance with the coefficients. Features far outside the fitted range are extrapolated linearly, without warning.

attempt gives the per-attempt features of one way of playing the item (a new song with 3 decoys); left None, the attempt is the fitted attempts’ average.

weights()[source]#

Each feature’s weight in logits of difficulty per unit of the feature.

Positive: more of the feature makes an item harder. The sd is the weight’s posterior sd; a weight within about two of zero is not distinguishable from “this feature does not matter”. Two features that move together split their weight between them, each with a wide sd.

Fit which item features predict difficulty, from a log of play.

features maps an item key to {name: value}; by default each item’s meta['features'] (item_features()). Every item answered in the log needs a finite value for every feature named anywhere, or the fit is refused rather than guessed. A right/wrong response counts as one trial, a score k out of max_score as k successes in max_score trials (the binomial reading that binomial_thresholds() gives a score; other step spacings are not modelled here); skips are not evidence about difficulty and are left out. Guessing is not modelled.

Per-attempt features. attempt_features reads, from each response, features of how that attempt was set up (by default response.meta['features'], see attempt_features(); None ignores them). They enter the same linear predictor, difficulty = intercept + w . x_item + v . x_attempt + residual_item, standardised over the fitted attempts and with the same weight prior, but with no residual of their own. If any scored attempt has them, every one needs a finite value for each, or the fit is refused. A given difficulty that anchors the scale is the item’s at the average attempt.

The scale. Every answered item that already has a difficulty can anchor the fit to the bank’s scale. anchor="location" (the default) fits on play alone and then shifts the intercept (and the students’ mean ability) so that the anchors’ fitted difficulties average their given ones: filled items land where the bank’s would, while the weights stay exactly what play says, whatever the bank’s spread (a published band from difficulty_from_rank() is an ordering, not a scale). anchor="exact" holds each anchor at its given value instead, which also lets the given values inform the weights; it trusts them, spread included, and a bank anchored throughout is then a regression of the given values on the features, with play only placing the students. anchor="none" keeps the fitted students’ scale (mean ability 0). A given difficulty of exactly 0 or 1 has no finite logit and is skipped as an anchor, with a warning.

What it assumes about the log. Each student has one ability over the log (learning within the window is not modelled, so fit on a window short enough for that). Which items a student was given may depend on their earlier answers, as an adaptive game’s choice does, but not on anything about them the log does not show: stronger students steered to harder items by some other route confound ability with difficulty, and no fit of this log can undo that.

The priors. Weights are per standard deviation of each feature across the fitted items, so weight_prior_var=1 says a one-sd change in a feature plausibly moves difficulty by up to a logit or two, whatever its units. residual_var (how far an item may sit from what its features predict) and ability_prior_var (how spread the students are) are estimated from the log when left None (empirical Bayes, by EM; the ability spread only with two or more students, else 1.0), which is what keeps the weights’ sds honest: fixed below the truth, the 95% intervals covered the true weights 72-80% of the time; estimated, 93-97% (docs/learner-model-design.md, decision 13). With around 15 responses per item the estimates run about 20% low, as Laplace estimates of variance components do on right/wrong data.

>>> import random
>>> rng = random.Random(0)
>>> bank = {f'q{i}': Item(f'q{i}', meta={'features': {'length': i % 6}}) for i in range(30)}
>>> log = {}
>>> for s in range(20):
...     theta = rng.gauss(0, 1)
...     log[f's{s}'] = [
...         Response(f's{s}', q, rng.random() < expit(theta - (0.6 * bank[q].meta['features']['length'] - 1.5)))
...         for q in bank]
>>> model = fit_feature_difficulty(log, items=bank)
>>> w = model.weights()['length']
>>> abs(w.mean - 0.6) < 2 * w.sd, w.mean > 2 * w.sd   # recovered, and it matters
(True, True)
>>> model.predict({'length': 5}).mean > model.predict({'length': 0}).mean
True
