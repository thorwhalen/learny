# Learner modelling in `learny` — the boundaries, decided up front

Date: 2026-09-20. Scope: `learny.tracing`, v1.

## What this is

A per-student model of what a learner knows, carrying **priors** that **update from that student's own data**. It is deliberately independent of any one application: it takes a bank of labelled items and a stream of responses, and answers two questions — *how likely is this student to get this item right?* and *which labels is this student weakest on?*

## The regime it is built for

This is the part that determines every other decision, so it is stated first.

- **Few learners.** One to a handful, often exactly one. Not a MOOC, not a classroom platform. A family, a tutor, a single teacher.
- **Sparse responses.** A student may have a hundred responses in total, spread over a hundred or more labels. Most labels will have between zero and three observations for that student. **Cold start is the normal case, not an edge case.**
- **An externally calibrated item bank.** Difficulty is often already known from a source better than the local data — a published pass rate, an official difficulty band, an exam board's statistics.
- **Multi-label items with uneven tagging quality.** An item exercises several skills at once, and the labels were not all assigned with equal confidence.
- **Outcomes that are not binary.** Many assessments distinguish a wrong answer from an unanswered one, and the difference is informative.

A method that only works after a thousand responses is useless here. That rules out most of the knowledge-tracing literature as a *default*, while leaving it available as a seam.

## The one-command test (the definition of v1)

```
v1 done when:  model.record(student, item, 'correct'); model.predict(student, other_item)
               returns a calibrated probability, and model.replay() reproduces it from the log alone.
```

Covered by `learny/tracing/tests/test_model.py::TestReplayContract`.

## The seam table

Four seams. Each is one keyword argument with a default that genuinely works, and each replacement is something that **already exists** — not something imagined.

**Would another surface need the core to change?** No. `LearnerModel` takes and returns plain data, the stores are already `MutableMapping`, and nothing touches process state. A CLI is `python-dispatching`'s job over the same facade; HTTP and MCP are the same functions again. The frontend case is the interesting one and still costs the core nothing: a browser client would reimplement the estimator rather than call Python, which is exactly why the per-student state is a **small, explicit JSON document** — two numbers per skill — rather than a pickled object.

## The five decisions that carry the design

### 1. The log is the source of truth; every estimate is a cache

The estimator **will** change — that is the entire premise of seam 1 — and a log that can be replayed makes that a re-run rather than a migration.

Enforced by `Estimator.observe` being a pure function of `(state, response, item)`, and asserted by `test_replay_reproduces_live_state`: folding `observe` over the whole log must reproduce, exactly, the state that live recording produced. If that test ever fails, the estimator has grown a dependence on something outside its inputs and is no longer swappable.

### 2. A posterior, not a point estimate

Each skill is a Gaussian `(mu, var)` on the logit scale, updated by one Newton step on the log-posterior — which is Glickman's Glicko update against an opponent of known strength, and equivalently the standard assumed-density filter for Bayesian logistic regression.

Carrying the variance is not ornamentation. It buys four things from one formula that would otherwise need four heuristics:

- **Cold start.** The step size *is* the posterior precision, so early responses move the estimate a long way and later ones refine it. There is no separate warm-up mode to get wrong.
- **Honest prediction.** Predictions integrate over the posterior (MacKay's probit approximation), so with no data the model reports something near the item's base rate *pulled toward a coin flip* — it knows the item, it does not yet know the student, and it says so.
- **A real confidence number.** `Mastery.confidence` and `Mastery.interval()` are posterior quantities, not a rescaled counter.
- **Forgetting without a guess about direction** (see 5).

Classical Elo is this same update with the information term frozen: Elo's `U(n) = a/(1 + b·n)` is exactly `1/(1/var + n·I)` for constant information `I`. So `gain='elo'` is not a rival estimator, it is this one with a constant step size — which matters because it means a consumer that wants plain Elo does not fork the model.

### 3. Item difficulty does not update by default — and that is the interesting part

Textbook Elo moves the learner's ability and the item's difficulty in opposite directions from the same residual. That is sound when many learners meet each item, because a population pins the item down.

**The common case here is one or two learners, ever.** At N=1, ability and difficulty are not jointly identifiable: they absorb each other, and you get a model that fits the history perfectly and predicts nothing. So the default treats item difficulty as **given**, from an observed external source, and updates only the learner. `update_difficulty=True` restores textbook Elo for anyone who actually has a population.

This is not a compromise. With a pre-calibrated item bank it is the better-founded model — online ability estimation against known item parameters, which is what adaptive testing has always done.

It is also why the Rasch form beats a per-label success/failure count. A Beta-Binomial tally cannot condition on the item's difficulty at update time: eight correct out of eight easy items and four out of eight mixed ones give it the same posterior. The Rasch form scores a correct answer on a hard item as more evidence, which is the whole point. (`difficulty_from_rank` is provided for banks whose published difficulty is an ordinal band rather than a measured rate — it is a prior, not a measurement.)

### 4. The pooling is across labels within one student, never across students

The question this design had to answer: how do priors pool without one student's data leaking into another's estimate?

**The default does not pool across students at all.** It pools across labels within one student:

```
logit P(correct) = global_skill + aggregate(label deviations) - item_difficulty
```

A label carries only a *deviation* from that student's own global skill, with a tight prior. With one or two observations the deviation stays near zero and the prediction falls back on the student's global skill plus the item's known difficulty; as evidence accumulates the deviation earns its place. One paper's worth of responses gives the global skill enough precision to serve as every label's prior **before any label-specific evidence exists**. The hierarchy is the cold-start mechanism, not a refinement on top of one.

Three consequences, all of them wanted:

1. **No other student need exist.** The single-student case is the default path, not a degenerate special case of a population model.
2. **The privacy boundary is structural, not procedural.** There is no code path by which one student's responses reach another's estimate. `test_one_students_data_never_touches_anothers_estimate` asserts it.
3. **The population term comes from the item bank**, which is an aggregate published by someone else and carries no individual's data.

If cross-student pooling is ever wanted, it belongs behind seam 1 as a deliberate act producing an **explicitly exported, versioned artifact** — so that what crosses between students is visible and reviewable — never as an implicit side effect of fitting.

`conjunctivity=` controls how labels combine: 0 (the default) is compensatory, a reliability-weighted mean in which strong labels offset weak ones; larger values approach weakest-link, where the label the student is worst at dominates. Real assessments contain both kinds of item, so this is a knob rather than a verdict. Label weights below 1.0 attenuate a label's influence, which is how a facet tagged with lower inter-rater agreement is stopped from moving an estimate as far as a reliably tagged one.

### 5. A skip is not a wrong answer, and not all skips are alike

`Outcome` has three values. Where an assessment's scoring rewards prudent abstention, an unanswered question is a signal about confidence and time, not about whether the student could have answered. Binarising at capture destroys that permanently, so the **log always records what actually happened** and the estimator decides what to make of it.

- A blank in the **trailing run** at the end of a sitting is a clock, not a judgement — `mark_not_reached` flags it and the default ignores it, the standard treatment for an item that was not administered.
- An **interior** blank, with answered questions after it, is a decision not to answer: a half-weight soft observation at the guessing rate. Scoring it as wrong is more biased than ignoring it; ignoring it is biased too, because abstention correlates with lower ability. A soft observation is the compromise, and it is stated as one.

`guess=` matters here and is left at 0 deliberately: the guessing rate is a property of the assessment (0.2 for five-option multiple choice), not of the model, and a wrong value quietly biases everything.

### 6. Forgetting inflates variance; it does not decay the mean

Before each update, a skill's variance grows with the time since it was last seen, capped at its prior. Inflating variance says *we know less now*, which is true. Decaying the mean would say *the skill got worse*, which is a guess — and for a learner who is also being taught elsewhere, quite possibly the wrong one. A stale belief simply re-opens so that new evidence moves it again.

## Deliberately out of scope for v1

- **Scheduling / spaced repetition.** A *retention* clock ("when should this come back?") and a *proficiency* clock ("how likely, right now?") are different models and should stay distinct. v1 is the proficiency clock only. When the retention clock is wanted, `t/kodokan/kodokan/learning.py` already implements `Leitner`, `SM2`, `FSRSLite` and `ConfusionWeighted` in Python behind a common interface, and already rebuilds state by replaying a history log — the same contract used here.
- **Item taxonomy, tagging and inter-rater agreement.** A different package: this one consumes a taxonomy, it does not define one.
- **Hyperparameter refitting.** The prequential replay in `learny.tracing.diagnostics` (`prequential()`) would fit `prior_var`, `label_prior_var`, `forget_per_week` and `abstain_weight` over a small grid. It needs no new seam: `compare_estimators` (#32) is the grid's scorer, one candidate per value, with the one-standard-error rule.

## Decisions of 2026-09-22 (issue #5): label dimensionality, pooling, scope

### 7. Model labels as given; measure whether they can be told apart; never collapse silently

The real-data finding — nine labels per item left every label indistinguishable from overall skill, one facet (~1.7 labels per item) gave four times the separation — is structural, not only a matter of sample size. In `_shares` each of an item's *k* labels gets share `1/k`, so it receives `1/k²` of the item's information per response. At nine labels that is 1/81; at 1.7 it is about 1/3. More data does not fix a design in which the labels never vary independently. Caveat: the "four times" was measured on *posterior* deviations, which the prior shrinks harder the less information a label gets, so it overstates how much projection helps; on synthetic data with partial co-tagging the separation of the wide and the projected models is much closer. The structural point stands only for labels that *always* co-occur.

- **Default: labels are modelled exactly as the item bank gives them.** Whether a taxonomy should be collapsed for modelling is a judgement about that taxonomy, and auto-collapsing would silently change what a label means.
- **The model now says when its ordering is noise.** `LearnerModel.separation(student)` returns the Rasch separation index over the label *deviations* (`G = true SD / RMSE`, reliability `G²/(1+G²)`, strata `(4G+1)/3`). `distinguishable` is `G ≥ 2` — reliability 0.8, about three strata, the usual bar for a ranking one acts on. The state holds posteriors, not the likelihood-only measures the classical formula assumes, so the index is read in its posterior (EAP) form: `G = sd(mu) / sqrt(mean(var))`, reliability `var(mu) / (var(mu) + mean(var))`. Fed shrunk posteriors, the classical `sqrt(var(mu) − mean(var)) / rmse` reads about `G² − 1` in place of `G²`, so separable labels read as noise (post-merge review of #10). #11 fixed that by de-shrinking each posterior with the estimator's `label_prior_var`. That inverse is only valid while the variance comes from the prior plus evidence, and `forget_per_week` re-opens a stale label's variance without moving its mean. With timestamped responses a day or a week apart, de-shrinking called pure noise distinguishable in most runs (post-merge review of #11). The EAP form needs no prior, matches the likelihood `G` in expectation under a correct prior, and forgetting can only lower it. It is conservative when the true spread is far wider than `label_prior_var`, and that is the safe direction for a gate on acting.
- **Projection is explicit and opt-in.** `restrict_labels(items, keep=...)` projects a bank onto one facet. It lives here, not in an item-bank package, because its signature is `Mapping[str, Item] -> Mapping[str, Item]` and needs no knowledge of any taxonomy.
- **`weakest(..., credible_below=z)`** returns only labels credibly weaker than the rest of the student's record; with indistinguishable labels it returns nothing, which is the honest answer. **This is the default** (`z = 1.0`, `DEFAULT_CREDIBLE_BELOW`); `credible_below=None` restores the plain ranking by posterior mean. The deviation comes through the estimator seam (`Mastery.deviation`), not the estimator's private state: an estimator that does not fill it gets a `TypeError` from the gated call rather than a silently empty answer. A negative `z` is refused. The result is a list subclass, `Weakest`, whose `.reason` says why it is empty (`no_evidence` or `no_credible_weakness`), because "no credible relative weakness" is not "nothing to practise".
- **The gate corrects for two things the first version did not (#14)**, each behind its own keyword-only option. *Shared shortfall* (`relative_to="labels"`, the default, `DEFAULT_RELATIVE_TO`): the online update does not carry the global/label covariance, so the split between "weak overall" and "weak on this label" came from the priors and part of a uniform shortfall landed on every label. A label is now compared with the precision-weighted mean of the student's *other* labels (leave-one-out; contrast variance is the sum of the two, treating the stored posteriors as independent), so a shortfall every label shares cancels. Evidence on a single label is therefore never a credible weakness under this default: there is nothing to compare it with. `relative_to="global"` compares with the global skill, as before, and is the right choice when unlabelled items carry the comparison. *Multiplicity* (`multiplicity="bonferroni"`, the default until #22 made it `"calibrated"`, decision 12): `z` now bounds the chance of a false flag across all `m` labels with evidence, via the per-label level `(1 - Phi(z)) / m`. Bonferroni rather than Šidák because the leave-one-out contrasts are slightly negatively correlated, where Šidák is a little lenient. `multiplicity="none"` applies `z` per label. `relative_to="global", multiplicity="none"` is exactly the original gate. Measured on 1000 simulated students per row (one label per item, 300 responses): with no real weakness, the original gate flags something for 56% of students at 6 labels and 81% at 20, the corrected gate for 7% and 0%; a student uniformly weak at −2.5 gets 2.58 of 6 labels flagged by the original gate and 0.00 by the corrected one. The bound is conservative because it is applied to posterior bounds, and a shrunk posterior's sd overstates how far its mean wanders under the null. The cost is power wherever evidence per label is thin. A real −2 logit weakness on one of 20 labels (~15 responses on it) is found 24% of the time, against 94% for the original gate. At 3 labels and 18 responses it is found 3% of the time, against 37%, while the original gate's false-flag rate there is only 5%. #22 replaced it with a correction calibrated to the null sampling spread (decision 12); #24 recorded the choice of default. Centring alone cancels a shared shortfall only when labels share items equally; with a heavily weighted label (`{"a": 0.9, "b": 0.1}`) it still flagged that label for 59 of 60 uniformly weak students. #23 fixed that in the estimator (decision 10).

### 8. Cross-student pooling: never implicit; if ever wanted, an exported, versioned prior

Confirmed as the shape, and nothing is built now — it needs a population, which is outside the regime this package is designed for. When it is wanted, a population artifact has two halves with two different homes:

- **Item difficulties** already enter through the `items=` seam, as an aggregate.
- **A population prior on label deviations** (`{label: (mu, var)}`) is a prior, so it enters as **one keyword argument on the estimator, `RaschEstimator(label_priors=...)`**, replacing the constant `Skill(0, label_prior_var)` a label starts from.

Either way the artifact is produced by a deliberate export step, versioned, and reviewable — what crosses between students is visible — never a side effect of fitting.

### 9. Scope: `learny.tracing` is the learner model; the item bank is a separate package

Item-label mapping, agent tagging, inter-rater agreement, per-label resource scoring and a faceted frontend belong to an **item-bank package that does not exist yet**. The contract between them is the one `learny` already has: the bank produces a `Mapping[str, Item]`, `Item(id, labels: Sequence[str] | Mapping[str, float], difficulty: float | None)`, with label weights carrying tagging reliability. **Dependency direction:** the bank may import `learny.tracing.records.Item`; `learny` never imports the bank.

The 11+ vocabulary game assets live in the repository under `games/eleven_plus/`, outside the package, so they are not part of the distribution (they were moved out of `learny/` before any first PyPI release). Whether and when that release happens is the owner's decision.

### 10. The estimator carries the global/label covariance (2026-10-13, #23)

The mean-field update moved each skill as if it alone explained the residual (`share * score / (1/var + share^2 * info)`), so the split between "weak overall" and "weak on this label" came from the priors and the shares: a label on every item with a 0.9 share absorbed about nine times the shared shortfall a 0.1-share label did, with a variance that shrank as if that were evidence. `RaschEstimator` now does one Laplace step on the *joint* posterior over the global skill and the labels: a rank-1 update of the covariance along `Cov(skill, s)`, where `s = global + sum(share * label)`.

- **Storage stays O(labels); an update costs O(labels on the item).** Labels are conditionally independent given the global skill (a star). Each label is stored as its regression on the global skill, `label = offset + beta * global + e` with `Var(e) = cond_var`; its marginal `(mu, var)` and its covariance with the global skill, `cov = beta * var_global`, are read back from that, and label-label covariance is implied as `cov_a * cov_b / var_global`. After each update the joint is projected back onto the star, keeping every `(global, label)` pair exactly (the KL-optimal projection onto that family). What is dropped is the residual correlation between two labels on the same item, given the global skill. A response leaves the regression of every label it does not name exactly unchanged (the likelihood involves only the global skill and the item's labels), so only the item's labels are rewritten. The first version of this decision stored each label's marginal `(mu, var, cov)` and so rewrote every label on every response, and scanned every label to predict: at 1000 labels, 7 ms per `observe` and 2.3 ms per `predict`, against 0.07 ms and 0.04 ms now (main: 0.33 ms and 0.04 ms; the review of #26 measured it).
- **Forgetting goes through a frame.** Drift on the global skill that leaves each covariance as it was changes every label's regression, by one affine map common to all labels (`beta *= r`, `cond_var += beta² var_global (1 − r)`, `offset += beta (1 − r) mu_global`, with `r = var_before / var_after`). The global entry accumulates that map as a `frame` (`scale`, `resid`, `shift`), and labels are stored relative to it (`slope`, `resid_var`, `offset`), so forgetting rewrites no label either. Stored slopes grow as `1 / scale`, so when the scale falls below `_FRAME_FLOOR` (0.01) every label is re-expressed in a fresh frame: O(labels), once per many weeks of drift, and it keeps reads exact to about 1e-12. A label's own drift is applied when it is next touched, capped at `label_prior_var` as on main.
- **Every label moves, not only the item's.** A label that covaries with the global skill moves when the global skill does (an unlabelled item now informs the labels): its mean is read as `offset + beta * mu_global`. Its `n` and `t` count only the responses that named it.
- **Backward compatible.** A state written before this layout stores labels as `(mu, var)`, with an optional `cov` (absent, `None` or 0 is the mean-field state). It reads unchanged: `mastery()` and `predict()` report the stored marginals. The first `observe()` on such a state re-expresses each label that has a covariance as a regression, once; labels without one stay as they are. Nothing is migrated, and `replay()` re-derives the state from the log. The reverse, an older version reading a state written now, is not supported.
- **Predictions and mastery use the joint.** `predict()` integrates over `h' Sigma h`, covariances included; `Mastery.skill.var` is `var_global + var_label + 2 cov`. `Mastery.loading` (`cov / sd_global`) lets `weakest()` count the covariance two labels share through the global skill when it contrasts them.
- **Separation is measured given the global skill.** Carrying the covariance gives a label's marginal variance a floor where the record cannot split "weak overall" from "weak on this label" (one label's items alone: the label takes the prior share, `0.25 / 1.25 = 0.2`, of the shortfall at every n, with sd ≈ 0.45). That shared direction moves all deviations together and blurs no ordering among them, so `label_separation` uses `var − cov² / var_global` (`var − loading²`) as each deviation's noise. Using the marginal variance had made separation more conservative than on main (9 single-label labels, true deviation sd 1.0, 300 responses: G 1.91 against 2.10, distinguishable for 37% of students against 63%); with the conditional variance it reads 2.10 and 63% again (2 labels per item, 1000 responses: 2.80 and 93%, main 2.81 and 93%).
- **Approximations.** Forgetting adds independent drift per skill and leaves `cov` alone; the `conjunctivity` soft-min shares are linearised at the posterior means; `gain="elo"` keeps Elo's fixed gain `elo_rate * h` on the item's own skills (a label Elo does not name keeps its mean, through the frame's `shift`) and tracks the covariance as Bayes would.

Measured on 60 synthetic students per row (300 responses, uniform skill −2.5, no real label deviation, 30 items each pairing one label with one of five others), students with any label flagged by the default gate, before → after: 0.9/0.1 shares 55 → 0, 0.6/0.4 26 → 0, hub label on every item 8 → 0 (the issue's own runs read 59, 27 and 6 before). Prequential log loss and ECE are unchanged to the third decimal across cold-start regimes (100 labels and 30–100 responses, 2 labels per item, 9 labels per item), and the power to find a genuine −2 logit single-label weakness is unchanged (20 labels, 300 responses: 0.28 vs 0.285).

### 11. Ordered scores: an optional score on the response, a Partial Credit estimator behind the seam (2026-10-19, #17)

A consumer scores attempts in stars (1–5, or three ordered levels such as 1/3/5), which a three-valued `Outcome` cannot hold. The log record and the estimator each gain one thing; nothing else changes.

- **`Response(score=k, max_score=m)`, optional and paired.** `score` is an `int` in `0..m` on consecutive levels: 1–5 stars is `score = stars − 1, max_score = 4`; three ordered levels are `0, 1, 2` of `2`, because a level that can never be observed is not a level and would bias the thresholds. `outcome` stays required and is the dichotomous view of the same attempt, so the default estimator is untouched. A skipped response cannot carry a score. An unscored response serialises exactly as before (no `score` keys), so existing logs are byte-for-byte what they were and older readers ignore the new keys. This is the one change to the record format since v1, and it is additive.
- **`PartialCreditEstimator` (Masters 1982), chosen over the Graded Response Model (Samejima).** It is `RaschEstimator` with one method replaced, `_likelihood(response, item, s, v_s)`, which returns what one response says about the item's linear predictor `s` (posterior `N(s, v_s)`): the gradient and information the rank-1 update takes, the unit-scale residual for a co-estimated difficulty, and Elo's fixed-gain step. For the PCM the log-likelihood's gradient and information are `k − E[X]` and `Var[X]`, so the joint global/label update of decision 10, forgetting, the frame and replay are reused unchanged. The gradient is bounded by `max_score` rather than by 1, so one Newton step at the prior mean overshoots on a surprising score out of many levels (0 of 100 from `N(3, 0.5)`: −11.6, against a true mode of −2.2; the adversarial review of #33 measured it). The PCM path therefore iterates, by safeguarded Newton in one dimension, to the posterior mode along `s` and takes the curvature there (a Laplace step, `mode_steps=50`; `mode_steps=1` is the plain one-step update). Elo's step is the unit-scale residual `(k − E[X]) / m`, so a full score moves Elo by at most `elo_rate`, as a right answer does. GRM would need the same two quantities and fits the same seam; PCM won because it stays in the Rasch family (the score is a sufficient statistic) and because of the next point.
- **Default thresholds are binomial, `tau_k = log(k / (m − k + 1))`.** Under them the score is binomial with step rate `expit(s)`, so the expected fraction of the maximum equals the right/wrong probability, and an externally calibrated `Item.difficulty` means the same thing however the item is scored, with no new parameters. A score out of `m` then carries up to `m` times the information of one right/wrong answer, which is strong for a noisy rating. `thresholds=` is the seam: a callable `(item, max_score) -> m logits`; steps spread wider apart carry less information. With `max_score=1` and `mode_steps=1` a score is exactly a Rasch right/wrong answer, but only at `guess=0`: a response with no score is scored by the Rasch path itself (guessing and skips included), and `guess` applies to those only — a score is never modelled as a guess. On a multiple-choice item that is also scored, set `guess` with that in mind.
- **`predict()` keeps the `Estimator` meaning**, the probability of a correct right/wrong answer; `expected_score()` and `score_probabilities()` answer for a score, integrated over the posterior with the same probit approximation (under binomial thresholds and `guess=0`, `expected_score == max_score * predict()` exactly; both approximate the posterior integral).
- **`LearnerModel.record(..., score=, max_score=)` are now named arguments**, so a caller that passed `score=` as a free meta key now has it validated as an ordered score (no caller in the repository did; logs with `meta["score"]` replay unchanged). Thresholds must be finite numbers, and `score`/`max_score` any integral type (a numpy integer is stored as `int`); an integral float such as `3.0` is refused rather than guessed at.
- **One response carries one score.** An attempt with several sub-scores (reaction, tempo, rhythm) is several responses, one per sub-score, each against its own item id labelled by its facet. A vector score would need a multidimensional likelihood and a wider record for no gain the facet labels do not already give. The owner's confirmation of this shape is tracked in #30.
- **Score calibration (2026-10-19, #31).** `score_calibration()` (and `LearnerModel.score_calibration()`) replays the log prequentially, as `calibration()` does, and scores each scored response's forecast distribution against the level observed. It reports log loss, the ranked probability score (which also charges for how far off a forecast was), each against the observed level frequencies per `max_score`, and a reliability table of expected against observed fraction of the maximum. A scored response goes into whichever report matches what the estimator forecasts (`reads_scores(estimator)`): `RaschEstimator` reads only `outcome`, so its scored responses stay in `calibration()`; a score-reading estimator moves them to `score_calibration()`, because its `predict()` does not forecast the caller's dichotomised outcome.
- **The threshold spread, from a log (2026-10-19, #32).** `fit_threshold_spread(log, *, items)` tries `spread_thresholds(c)` for `c` in 1/3–3. These are binomial thresholds stretched by `c`, so `c = 1` is the default and an item's difficulty stays at the middle of its scale. The candidates are compared by prequential score log loss through `compare_estimators`, the general tool for refitting any estimator setting on a log. A prequential arg-min leans toward sharper forecasts than the truth on short histories (the #36 review measured it), so the choice uses the **one-standard-error rule**: keep the spread nearest the default whose loss is within one paired, student-clustered standard error of the best. On 20 simulated students (20 replications per row), the true spread was picked:

| true spread | responses per student | arg-min | one-SE rule |
|---|---|---|---|
| 0.5 | 30 · 120 | 10 · 19 of 20 | 14 · 20 of 20 |
| 1.0 | 30 · 120 | 12 · 19 | 16 · 20 |
| 2.0 | 30 · 120 | 19 · 20 | 17 · 20 |

  The rule gives up a little at true 2.0 on short histories (3 of 20 pulled to 1.33) for a large gain where the default is right. **With one to three students it keeps the default unless the log is clear**: at true 2.0 it chose 2.0 in 11–15 of 30 fits (arg-min 17–26), and at true 0.5 with one student it kept 1.0 in 13 of 30 (adversarial review of #41). A single global spread cannot see items whose spreads differ (0.4 and 2.5 mixed came out as 1.0); per-item thresholds learned from a population are #40. A full fit replays the log once per candidate: 29 s for 30k responses and 7 spreads. Candidates that disagree on what they forecast (a Rasch estimator among partial-credit ones) are refused, because their log losses are on different events.

### 12. weakest() is calibrated to the null, not to the posterior (2026-10-19, #22)

The Bonferroni gate of #14 bounded the chance of any false flag by applying `(1 − Φ(z)) / m` to *posterior* bounds. A posterior mean is shrunk, so it stays well inside its posterior sd: with little evidence the real false-flag rate was ~0 against a 16% target, and power was lost where it bought nothing (3 labels and 18 responses: a real −2 weakness found 1% of the time).

- **`Mastery.null_var`: the label's own sampling variance under "no real deviation", tracked, not derived.** The conjugate identity `null = v − v²/τ²` is what forgetting broke in #11: forgetting re-opens `v` without moving the mean. So the default estimator carries the null variance in the state (`nv` on each label entry) and updates it with the same linearised step as the mean, `nv' = (1 − g·I·share)²·nv + g²·noise`, where `noise` is the gradient's sampling variance (`I` for an answer; for a skip the bound `jump²`, see below). Forgetting leaves `nv` alone because it leaves the mean alone. A label never seen has `nv = 0` (its prior mean is exact). A label stored before tracking starts at its posterior variance (conservative). It is tracked under `gain="bayes"` only.
- **The gain is the stored offset's, `g = (u − β'·u0) / (1 + I·v_s)`, not the label's full gain `u / (1 + I·v_s)`.** A label's posterior mean moves partly with the global skill, and that part is common to every label: in a leave-one-out contrast it cancels exactly when the shared part is a common subtraction. With the full gain the global skill's absorption of each residual made the labels' sampling errors negatively correlated and the contrast's spread 14–25% wider than predicted (√(L/(L−1)) at L labels). With `share·cond_var` alone it was right until the global skill forgot, and 13–18% too narrow after. The exact offset coefficient, which includes `(β − β')·u0`, measures 0.96–1.03 of the empirical spread across 3–20 labels, daily to monthly spacing, and forgetting at 1× and 5× the default rate.
- **The shared part of the contrast keeps its posterior size.** The posterior contrast variance is each label's own residual plus `(loading_i − Σ w·loading_j)²`, the direction in which the record cannot tell "weak overall" from "weak on this label". Only the own residuals are replaced by `null_var`. Replacing the shared part too flagged the heavily weighted label for 20 of 20 uniformly weak students in the #23 setting (`{"l0": 0.9, other: 0.1}`): there a label's mean is moved by the priors' split of a shortfall, not by chance.
- **The null is skewed, and a many-label test lives in its tail.** A student who mostly gets a label right makes a rare wrong answer a large one-sided drop. The variance was right there (0.92 of the empirical), but with items at 0.05 and 20 labels × 2 responses, `P(z < −2.41)` was 0.054 against Bonferroni's per-label 0.0079, so 64% of students with no weakness were flagged (the adversarial review of #34 found it). So the state also carries each label's third cumulant (`nk3`, `Mastery.null_k3`), updated with the same recursion cubed, `nk3' = (1 − g·I·share)³·nk3 + g³·noise3`. The contrast's skewness is `(k3_i − Σ w³·k3_j) / sd³`. The per-label critical z gets a first-order Cornish–Fisher correction, `z + (z² − 1)·max(0, −skew)/6`. It is only ever made stricter: a positive skew would move the bound in, which is where the expansion is least reliable. The worst cell fell from 0.64 to 0.07, and every off-grid cell the review found (easy items, θ = +3, partial-credit scores) is now at 0.01–0.15. The sparsest of these are handled by the rule in the next point.
- **Below one rare event, no expansion holds.** With one or two responses per label on items the student gets right 95–99% of the time, a label's null is a single discrete event: one wrong answer. Cornish–Fisher was still at 0.23–0.30 false flags there (second review of #34, 2000 students per cell), and its error jumped between neighbouring cells. A compound-Poisson fit to the two tracked cumulants puts `λ = nv³ / nk3²` rare jumps behind a label's null, and `λ` does not depend on the gains. A label with `λ < 1` (`_MIN_RARE_EVENTS`) is measured by its posterior own residual instead, as `"bonferroni"` would measure it. Those cells fell to 0.000–0.009. Their power falls with them, to about what `"none"` has there (~0): one wrong answer among a few right ones is not evidence of a weakness. The acceptance grid, at p ≈ 0.5, has `λ` far above 1 and does not change. #35 tracks an exact tail that could recover the power.
- **A skip is not noise-free.** Its target is fixed, but whether the student skips is random at a rate `q` the model does not know, and any response could have been a skip. Over `N` responses that adds `N·q(1 − q)·jump²`, which is `(1 − q)·jump²` per skip that happened. The bound `jump²` (third cumulant `jump³`) is charged per skip. Charging nothing let random skips at 30% raise false flags to 0.22; now they stay at 0.15.
- **`multiplicity="calibrated"` is the default**: Bonferroni's per-label z on the calibrated spread, corrected for skew. `"bonferroni"` (the posterior bound) and `"none"` stay. An estimator that does not fill `null_var` gets exactly `"bonferroni"`.
- **Measured** (one label per item, items at 0.5, global skill ~ N(0, 1), real deviation −2 on one label, 1000 students per cell; F = students with no real weakness flagged, P = the weak label found; script and logs under `$PP/_agent_work/learny/2026-10-19-weakest-null-calibration/`):

| labels / responses | spacing | none F / P | bonferroni F / P | calibrated F / P | oracle P at F = 0.16 |
|---|---|---|---|---|---|
| 3 / 18 | none · week · month | 0.06 / 0.29 · 0.05 / 0.27 · 0.05 / 0.26 | 0.00 / 0.01 | 0.13 / 0.41 · 0.12 / 0.39 · 0.13 / 0.39 | 0.41–0.42 |
| 6 / 60 | none · week · month | 0.24 / 0.65 · 0.21 / 0.62 · 0.21 / 0.62 | 0.00 / 0.09–0.12 | 0.13 / 0.56 (all three) | 0.61–0.62 |
| 20 / 300 | none · week · month | 0.73 / 0.86 · 0.70 / 0.85 · 0.69 / 0.85 | 0.00 / 0.16–0.26 | 0.10 / 0.63 · 0.12 / 0.62 · 0.11 / 0.62 | 0.62–0.65 |

  The oracle is the best power any recalibration of the posterior-bound statistic can have at a 16% false-flag rate, found by simulating the null. The calibrated gate is within 0.03 of it everywhere. **The stated margin against `"none"`:** +0.12 at 3/18; −0.06 to −0.09 at 6/60, where `"none"` false-flags 21–24% of students; −0.23 at 20/300, where `"none"`'s power is bought with 70% false flags.
- **Robustness** (400–600 students per cell, weekly):
  - False flags stay at 0.02–0.17 for items at random difficulty, two labels per item, unequal label frequencies, `guess=0.2` and `conjunctivity=2`.
  - Off the grid they stay at 0.00–0.15: items at 0.01–0.3, θ = ±3, 1 to 2 responses per label on near-certain items, 20 labels × 40 responses, partial-credit scores, random skips up to 30%.
  - The #23 guarantee holds. A uniform shortfall or surplus (θ = ±1, ±2.5) with 0.9/0.1 or 0.7/0.3 weights, a hub label or a half-hub label is flagged for at most 0.15 of students.
  - A −1 weakness is found 18–19% of the time (`"bonferroni"`: 0–1%).
  - Under `relative_to="global"` the gate is more cautious (0.03–0.11 false flags), because the part of a label's spread that it shares with the others is counted there, not cancelled.
- **Approximations.** The recursion linearises at the posterior mean. It treats the labels' own sampling errors as independent of each other and of the global skill's. It leaves out the `β·μ_g` term, whose variance measures below 1% of the contrast's. The skew correction is first order, and below one rare event the gate gives up rather than guess: it is a tail adjustment, not an exact discrete tail. A null that needs more than two cumulants (a saddlepoint, or an exact Poisson-binomial tail over a label's responses) would need per-response weights, which this state does not keep. A label without `nv` (stored before this change and not seen since, or from an estimator that does not track it) contributes its posterior own residual in place of `null_var`; with none tracked the gate is exactly `"bonferroni"`.

### 13. Which item features make an item hard: an offline LLTM, exported through `items=` (2026-10-19, #18)

A bank can give every item hypothetical difficulty features (a song's glyph count, rhythmic irregularity, word frequency), and the owner wants play to say which of them matter. That is explanatory IRT: the Linear Logistic Test Model (Fischer 1973), `difficulty = intercept + weights · features`, with a residual per item (the random-item extension, De Boeck 2008).

- **Shape: an offline fit, not an estimator seam.** `fit_feature_difficulty(log, *, items, features=None, ...)` reads across students, so it follows decision 8. It runs only when called, over a log it is handed. What it learns leaves as an exported, versioned artifact, `FeatureDifficulty` (`to_dict()` with a `schema` tag, `from_dict()`), that enters the learner model through the `items=` seam that already exists: `apply(items)` fills each item's difficulty from its features. So no estimator changes, and per-student updates stay single-student. The issue left the seam open (`difficulty_model=`); an estimator-side seam would have made pooling a side effect of recording, which decision 8 rules out.
- **Model.** `logit P = ability[student] − (intercept + w · z[item] + residual[item])`, with Gaussian priors on everything: ability `N(μ, σ²)`, weights `N(0, 1)` per *standard deviation* of each feature across the fitted items (so the prior means the same thing whatever a feature's units), intercept `N(0, 4)`, residuals `N(0, τ²)`.
- **The scale is the bank's location, play's spread.** An answered item that already has a difficulty can anchor the fit. Without anchors the scale is the fitted group's own (mean ability 0): students averaging +2 logits on a half-published bank put the filled items 1.9 logits off the published ones (adversarial review of #37, 40 fits).
  - **`anchor="location"` (the default)** fits on play alone, then shifts the intercept and the students' mean ability so the anchors' fitted difficulties average their given ones. The shift is a linear map of the fitted coefficients and residuals, so the covariance follows; it takes the residual–residual covariances between anchors as 0. The weights are exactly play's. Bias on new items was +0.02 to +0.03 with 2–30 anchors, new-item coverage 0.89–0.92 (150 fits).
  - **`anchor="exact"`** holds each anchor at its given value and lets the given values inform the weights. It trusts them, spread included: a published scale half as wide as play's (an ordering from `difficulty_from_rank`, say) cut weight coverage to 0.33 (review round 2). A bank anchored throughout is then a regression of the given values on the features, with play placing only the students. Use it when the given values are a calibrated scale.
  - `anchor="none"` keeps the fitted group's scale. A given difficulty of exactly 0 or 1 has no finite logit and is skipped as an anchor, with a warning: one such pair had pushed `τ²` from 0.28 to 8.5.
- **Identification.** A log where every answer is right, or every one wrong, does not identify difficulty, and the fit warns that it is the priors'. A student with a perfect record is fine: the ability prior holds them. It is fitted by MAP (Newton) with a Laplace covariance. The item residuals are eliminated by Schur complement, so the dense algebra is over students + features only and the fit stays pure stdlib (0.02 s for one student × 200 items, 0.17 s for 50 students × 40 responses with 6 features).
- **Data.** Right/wrong is one trial; a score `k` of `max_score` is `k` successes in `max_score` trials, the binomial reading of the default partial-credit thresholds (decision 11). Skips are not evidence about difficulty. Each student has one ability over the log: learning during the window is not modelled.
- **`τ²` and `σ²` are estimated by default (EM).** Weight sds are only honest if they are right. Fixed below the truth, 95% intervals covered the true weights 72–80% of the time (`τ²` 0.25 for a true 1.0; `σ²` 1 for a true 9). Estimated, they cover 93–97% and a new item's prediction 90–95% (200 simulated fits per row, 1–60 students, 30–60 responses each, 3 features). With around 15 responses per item the estimates run about 20% low, the known downward bias of Laplace / PQL variance components on binary data. After the review fixes, on 200 fits per row: 30 students × 30 responses 0.93 (new item 0.91); one student × 60 0.97 (0.96); ability sd 3 0.93 (0.93); `τ²` = 1 0.93 (0.90); items chosen adaptively from earlier answers 0.90 (0.92). Weights come back about 10% toward zero (0.70–0.74 for a true 0.8), the prior's shrinkage and the Laplace attenuation on binary data; read a weight's sign and size against its sd, not as an exact effect. With a single student `σ²` stays at 1 (it cannot be estimated from one). Fixed values are still accepted. EM stops at a 1% relative change; failing to converge in the final Newton fit or in EM (`max_iter`, `max_em_iter`) warns (`RuntimeWarning`) and sets `converged=False` on the artifact.
- **What it assumes about the log.** One ability per student over the window, so learning during it is not modelled. Item choice may depend on a student's *earlier answers*, as an adaptive game's does, but not on anything about them the log does not show: steering stronger students to harder items by an outside route confounds ability with difficulty (the review measured weight coverage 0.39 for that). Scores are read as binomial; other step spacings are not modelled (#32 would add a `thresholds=` keyword). Features far outside the fitted range are extrapolated linearly.
- **Refusals over guesses.** An answered item missing from the bank, without features, missing one feature, or a feature constant across the fitted items, each raises with the offending ids.
- **Outputs.** `weights()`: each feature's weight in logits per unit, with sd. `predict(features)`: a new item's logit difficulty with sd, including `τ²`. `predict(features, item_id=...)` for a fitted item adds its own residual, with its posterior variance and covariance with the coefficients. `apply(items, overwrite=False, use_residuals=False)` writes the proportion-failing difficulty the bank uses, **from features alone by default**. A fitted residual carries the fitted students' answers: with one learner it correlated −0.86 with that learner's own correct rate, and feeding it back to estimate the same learner counts their answers twice. Per-attempt features (decoys, mix) are #38.

### Calibration reporting (was "the most important next step")

Built: `LearnerModel.calibration()` / `diagnostics.calibration()` replays the log prequentially — each prediction is made from the state before its own response — and reports log loss against the know-only-the-base-rate baseline, Brier score, expected calibration error and a reliability table. Each student is replayed alone, exactly as in live use; only the scored pairs are pooled. Ordered scores have their own report, `score_calibration()` (decision 11).

## Data, and the line it does not cross

`learny` is a **public** repository. Per-student responses are personal data, and the first consumers' learners include children.

- Every example, doctest and fixture in this package is **synthetic**.
- Real responses live under `~/.local/share/learny/`, never in a repository. The default store root is the policy: a store defaulting to `./data` would invite every caller to commit it.
- `LEARNY_DATA_DIR` overrides the root for tests and CI.
- One file per student, so one learner's data can be audited, handed over or deleted on its own.
- Nothing derived from a private consumer project — its data, its measurements, or its identity — belongs in this repository. Consumer-specific integration notes live in that consumer's own repository.
